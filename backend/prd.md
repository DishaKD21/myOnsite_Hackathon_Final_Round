# 90. BackupChain — Incremental Backup Chain Integrity Under a Missing Delta

**90. BackupChain — Incremental Backup Chain Integrity Under a Missing Delta**
**Problem Statement**
Incremental backups are useful only if every delta required to reconstruct a chosen recovery point is present and internally consistent. A backup catalog can still claim a chain is complete after one delta was never uploaded, was truncated, or was replaced by a similarly named artifact, causing recovery to fail only after a disaster. Design a bounded backup system with one full backup and several ordered incrementals, each carrying machine-checkable coverage metadata and content evidence. The system must verify the chain before restore, identify the earliest missing or inconsistent segment, determine the newest recovery point that is genuinely reconstructable, and use an alternate overlapping delta when the evidence proves it is equivalent rather than blindly trusting catalog order. It must refuse a recovery point whose required history cannot be proven complete. A convincing demonstration should use explicitly uploaded source data, then reconstruct the latest safe state and verify it against that user-provided data.
